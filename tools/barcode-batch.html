Choosing a format

UPC-A is the 12-digit format used on retail products in the US and Canada. EAN-13 is the international equivalent (13 digits) used almost everywhere else, and is also what most UPC-A codes are stored as once padded with a leading zero. Code128 is different in kind — it isn't tied to a fixed digit count or a retail product-numbering scheme, and can encode any alphanumeric string, which makes it the right choice for internal codes, asset tags, or anything that isn't a registered retail product number.

How it works

Each barcode is rendered locally (via the open-source JsBarcode library) — to a canvas for PNG output, or as SVG vector markup — the same fundamental technique any barcode generator uses, just running entirely on your device instead of a server. You can confirm nothing is uploaded by checking your browser's Network tab while a batch runs. See this post for when generating dozens or hundreds at once actually comes up in practice, beyond one-off product labels.

Limits

Up to 100 codes per batch. EAN-13 and UPC-A require the correct digit count and a valid checksum digit at the end — codes that don't validate are skipped and listed separately, each with the reason, rather than silently producing a broken barcode, since a barcode that fails to scan at checkout is a worse outcome than an obvious error message. Spaces and hyphens inside EAN/UPC numbers (0 36000 29145 2, 036000-291452) are stripped before checking.

FAQ

Can I generate a barcode for a product I'm about to sell on Amazon or another marketplace?

Technically yes, this tool will produce a valid UPC/EAN barcode from any correctly-formatted number — but most marketplaces require the underlying number itself to be registered through GS1 (the organization that issues UPC/EAN prefixes) to avoid conflicting with another seller's product. This tool handles the barcode image; it doesn't register or validate ownership of the number itself. If you're not sure which format your marketplace actually expects, this comparison breaks down where UPC-A, EAN-13, and Code128 are each used.

What happens if I enter a 12-digit number and select EAN-13?

A 12-digit number means one of two different things, and the tool can't guess which. It might be a complete UPC-A (12 digits including its check digit) — in that case select UPC-A; the same product as an EAN-13 is simply the UPC with a leading zero. Or it might be the first 12 digits of an EAN-13 whose check digit was never added — common when numbers come out of a spreadsheet or an ERP export. In that case set Check digit to Missing — calculate it and the 13th digit is computed for each line and shown under the barcode.

My list of EAN numbers has no check digits. Can the tool add them?

Yes — choose Missing — calculate it. Enter 12 digits per line for EAN-13 or 11 for UPC-A. The check digit is the standard GS1 mod-10: counting from the rightmost digit, multiply alternately by 3 and 1, add the results, and the check digit is whatever brings the sum up to the next multiple of 10. The downloaded file is named after the full code, so you can match each PNG back to its row. Leave the default Included — validate it on when your numbers are already complete: a wrong last digit is then caught as a probable typo instead of being quietly replaced.

Why did some of my codes get skipped?

For EAN-13 and UPC-A, a code is skipped if it isn't purely numeric, isn't the exact expected length, or fails the format's built-in checksum validation (the last digit is calculated from the others specifically to catch typos and transcription errors). Code128 has no such restriction and accepts any alphanumeric string. Each skipped code is listed with its reason — including, for a checksum failure, which last digit the number should have had.

Can I paste two columns from Excel or Google Sheets?

Yes. Select the code column and a name column next to it (code first) and paste. Each row arrives as code, tab, name. The tool encodes only the first column and uses the name for the downloaded file, so SKU-0042 next to "Blue mug" becomes blue-mug.png in the ZIP, and the name is shown under each preview. The tab is never put into the barcode itself, which matters for Code 128. Code 128 can encode a tab character, so a tool that encodes the whole pasted line produces a barcode that scans as SKU-0042 followed by an invisible tab and the product name. Rows with the same name get -2, -3 suffixes instead of overwriting each other. If the cells came out of Excel as numbers, see the spreadsheet question below.

Code 128 A, B or C — which one should I pick?

Pick auto unless a system or a spec tells you otherwise. Code 128 has three character sets, and a single barcode can switch between them. Auto starts in whichever set produces the shortest barcode and switches when it needs to, the way most label software does. All three read back as the same text: a scanner reading ABC123 returns ABC123 whichever set encoded it, so the choice changes only the width of the barcode and the characters it is allowed to contain.

  • Set B holds the printable characters: upper and lower case letters, digits and punctuation. Choose Code 128 B when a label spec or an older system explicitly asks for "Code 128B".
  • Set C packs two digits into each symbol, so it is the narrowest option for long numbers. It accepts digits only, and an even number of them. An odd count is rejected with the reason rather than padded silently, because adding a leading zero changes the value your system receives. Auto mode encodes the odd digit in set B instead. If a barcode you already have scans with an unexpected leading zero, that padding is the usual reason.
  • Set A holds upper-case letters, digits and control characters, with no lower case. It is rarely needed outside legacy industrial systems.

Characters outside a chosen set (lower case in A, a tab in B, letters in C) are skipped and listed, and so is anything outside ASCII (accented letters, curly quotes, non-Latin scripts), which Code 128 can't encode at all.

Can I print them all on one sheet, or save them as one PDF?

Yes. After generating, use Print sheet / Save as PDF under the results and choose how many barcodes go in each row. Every barcode is re-drawn as vector graphics for the sheet, so it prints sharp even when you picked the small PNG output. In the print dialog, choose your printer or Save as PDF to get a single file. Keep scaling at 100% ("Actual size"). The dashed borders are cutting guides. UPC-A and EAN-13 are placed at their standard 100% size (about 31 mm of bars, 23 mm bar height), whatever the row count, as long as they fit. At 4 per row they fit on A4 and Letter. At 5 per row the cells are too narrow, so they shrink to about three-quarters of that size, below GS1's 80% minimum for retail checkout, and the sheet warns you. Code 128 fills the cell width, so long values get thin bars at 4–5 per row, and 2 or 3 per row is safer for those. This is a plain grid, not a template for a specific label stock such as Avery sheets.

Does it work offline?

Once the page has loaded, yes. Everything runs in your browser, so you can disconnect and keep generating, downloading and printing. The only network requests happen when the page first loads, to fetch the open-source barcode and ZIP libraries it is built on.

Which output should I pick for printed labels?

SVG if your label or design software accepts it (most do — Illustrator, Inkscape, Affinity, Canva, Word, and most label programs). It's vector, so it stays sharp at any size and you can scale it to exactly the width you need. PNG — large draws every bar 4 pixels wide, which at 300 dpi comes out close to the nominal 100% size of a retail UPC-A (a 0.33 mm narrow bar, about 37 mm across including the margins). The default PNG — screen size is fine for spreadsheets, web pages, and previews, but it's small enough that a printer has to enlarge it. Enlarging a bitmap softens bar edges, and soft edges are what make scanners hesitate. Whichever you use, scale the barcode as a whole — stretching it in one direction only changes the bar-width ratios. For retail checkout, GS1 allows roughly 80% to 200% of the nominal size.

My codes came out of Excel and some are rejected

Spreadsheets damage barcode numbers in two predictable ways, and the skip list names both. Leading zeros get dropped, because Excel treats the column as a number, so the UPC 036000291452 arrives as the 11-digit 36000291452. When adding the zero back gives a valid code, the tool says so and shows the full number. Long numbers turn into scientific notation (4.00638E+12), and by then the real digits are gone from the cell, so no tool can recover them. In both cases the fix is in the spreadsheet: format the column as Text before pasting or importing the codes, then copy them again. Why Excel mangles long numbers covers the details. One trap to watch for in Missing — calculate it mode: an 11-digit UPC that only lost its leading zero looks exactly like a UPC body that is missing its check digit. When both readings produce a valid code, the result carries a warning so you can check before printing.

Can this make EAN-128 / GS1-128 shipping labels?

No. GS1-128 (the format still widely called EAN-128 or UCC-128) looks exactly like Code128, but it begins with a special FNC1 character and carries data in Application Identifiers such as (01) for a GTIN or (17) for an expiry date. The Code128 option here produces plain Code128 without FNC1, so typing (01)… into it gives you a barcode that scans but that a GS1 receiving system won't parse as structured data. For carton and pallet labels use GS1-aware label software. Why EAN-128 isn't an alternative to UPC explains where each one belongs.
